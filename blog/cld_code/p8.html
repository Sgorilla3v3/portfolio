실전 워크플로우: Explore–Plan–Code–Commit

복잡한 변경을 안전하게 처리하는 4단계 프로세스 패턴

Best Practice
1

Explore

탐색 및 이해

코드를 수정하기 전에 관련 파일과 구조를 파악합니다. 이 단계에서는 코드 작성을 금지합니다.

  • 관련 파일/문서 읽기
  • 현재 아키텍처 요약 요청
Prompt Example:

인증 관련 파일(src/auth/*)만 읽고 현재 구조를 요약해 줘.

# 중요: 코드는 아직 수정하지 마.

2

Plan

전략 수립

문제 해결을 위한 상세 계획을 수립합니다. 복잡한 작업일수록 think 모드를 활용하세요.

  • 단계별 체크리스트 작성
  • 잠재적 리스크/사이드이펙트 검토
Prompt Example:

로그인/비로그인 상태 모두 지원하기 위한 계획을 세워줘.

think hard about edge cases.

3

Code

구현 및 테스트

승인된 계획에 따라 코드를 작성합니다. 한 번에 하나씩, 작은 단위로 변경합니다.

  • 계획된 순서대로 구현
  • 단위 테스트 작성 및 실행
  • 린트/타입 에러 수정
Prompt Example:

계획의 1번 항목부터 구현을 시작해.

테스트를 먼저 실행해서 실패하는지 확인해줘.

4

Commit

검토 및 완료

작업 결과를 마무리하고 문서화합니다. 에이전트가 PR 메시지까지 작성하도록 합니다.

  • 커밋 메시지 자동 생성
  • PR 생성 및 요약
  • README / CHANGELOG 업데이트
Prompt Example:

작업 완료했으면 커밋하고 PR 올려줘.

관련 문서도 업데이트해줘.
