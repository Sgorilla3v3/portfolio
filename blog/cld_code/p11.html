명확하고 구체적인 지시로 AI 에이전트 성능 극대화

Best Practices

핵심 작성 원칙

구체적 지시와 범위 제한

모호한 요청 대신 구체적 파일명, 경로, 예상 산출물을 명시하세요. 숨겨진 제약 사항은 성능 저하의 주원인입니다.

단계적 의도 선언

"지금은 코드를 쓰지 말고 읽기만 해", "계획만 세워줘"와 같이 현재 단계의 작업 범위를 명확히 선언하세요.

풍부한 컨텍스트 제공

스크린샷, 다이어그램, 관련 GitHub 이슈 URL을 제공하세요. Tab 키 자동완성으로 정확한 파일 경로를 참조하는 것이 좋습니다.

운영 습관

  • 조기 중단 (Early Stop)

    AI가 잘못된 방향으로 가면 주저 말고 Esc 키로 중단하고 지침을 수정하세요.

  • 컨텍스트 주기적 초기화

    긴 세션은 성능을 저하시킵니다. 작업 단위가 바뀔 때마다 /clear 명령어로 컨텍스트를 비우세요.

프롬프트 비교 (Bad vs Good)

PROMPT_LOG.md

// Case 1: 테스트 코드 추가

Bad

foo.py에 테스트 추가해줘

Good

foo.py에 새로운 테스트 케이스를 작성해 줘. 사용자가 로그아웃된 엣지 케이스를 다루고, 모의(mock) 객체는 사용하지 마.

// Case 2: 레거시 코드 파악

Bad

이 API 왜 이래? 설명 좀.

Good

ExecutionFactory의 git 히스토리를 살펴보고 API가 어떻게 현재의 모습이 되었는지 배경을 요약해 줘.

복잡한 작업은 체크리스트로

대규모 작업 시 TODO.md 파일을 만들고 각 항목을 순차적으로 처리하도록 지시하면 안정성이 향상됩니다.
